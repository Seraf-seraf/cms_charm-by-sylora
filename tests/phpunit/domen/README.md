# Доменные тесты проекта

Каждая предметная область хранит тесткейсы в собственной поддиректории. Тесты нельзя добавлять непосредственно в `tests/phpunit/domen`.

Текущие домены:

- `support/TestBootstrap.php` отвечает за инициализацию и восстановление тестового окружения.
- `support/BrowserTestCase.php` отвечает только за lifecycle PHPUnit и запуск browser-сценария.
- `analytics` — согласие на аналитику, cookie-плашка и загрузка счетчиков; доменные runner и объект результата находятся в `analytics/support`.

Функциональные browser-тесты используют Testcontainers и официальный образ MariaDB
`mariadb:10.11.19`. Для запуска необходимы Docker Engine, PHP `mysqli`/`gd`,
POSIX extension, `setsid`, Node.js версии `20.10.0` или новее и Chrome/Chromium.
Node можно выбрать переменной `SYLORA_NODE_BIN`; без неё используется Node из
`PATH`. Для Node 20.10–21 browser runner включает `--experimental-websocket`, а
для Node 22 и новее использует встроенный `WebSocket` без флага. Browser runner
использует deadline 90 секунд по умолчанию; его можно изменить целым значением
`SYLORA_BROWSER_RUNNER_TIMEOUT_SECONDS` от 1 до 600. stdout и stderr читаются
одновременно. Node запускается только после подтверждения отдельной session.
`phpunit.xml.dist` включает `failOnSkipped="true"`: пропущенный тест делает
прогон неуспешным.
При timeout завершается только созданная для runner process group. Если direct
процесс остаётся активным после SIGKILL, runner сообщает об этом и пропускает
блокирующий `proc_close`; ОС может не завершить процесс в установленный срок.
Тестовая база создаётся из schema-only fixture
OpenCart 3.0.5.0, затем применяются миграции проекта. Каждый запуск использует
случайные реквизиты контейнера, временный конфиг из
`support/fixtures/test-config.php.template`, отдельные каталоги storage/image и
локальный HTTP-порт; `upload/config.php` не загружается. Для встроенного PHP-сервера
из fixture `support/fixtures/php-server-router.php` копируется router в одноразовый
temp-root: он передаёт несуществующие локальные пути OpenCart через `_route_`,
сохраняя query-маршруты и статическую раздачу `/catalog/...` и `/image/...`.
Шаблон автоматически заполняется значениями текущего контейнера и генерирует
конфиг только в одноразовом каталоге `/tmp/sylora-functional-tests-*`.
Синтетические данные для
проверок включают страницы согласия, товары и баннеры; изображения баннеров
берутся из локальных test fixtures, demo INSERT из upstream schema не импортируются.
Тесты и миграции выполняются в штатном строгом `sql_mode`. Только SQL-сессия
миграции `2026_07_06_000001_ru_ru_language.sql` временно работает без строгих
флагов: она выполняет `INSERT` без `language.image`, и MariaDB проверяет это поле
до условия `WHERE NOT EXISTS`, даже если строка `ru-ru` уже есть. Режим сессии
восстанавливается в `finally`; последующие миграции и PHP-сервер остаются в
строгом режиме.
Контейнер, PHP-сервер и временные каталоги удаляются при завершении тестового
процесса. Ошибка подготовки окружения завершает тест ошибкой, не пропуском.
Cookie-consent browser runner перехватывает каждый запрос через CDP: запросы к
локальному storefront проходят, `mc.yandex.ru/metrika/tag.js` получает
синтетический ответ, остальные внешние запросы блокируются до сети. Тест
проверяет, что запрос к tag отсутствует до согласия и появляется после явного
разрешения аналитики. `ProductActionsFunctionalTest` также блокирует все
cross-origin browser-запросы и завершает сценарий ошибкой при любой попытке
внешнего запроса.

Запуск всех доменных тестов:

```bash
./upload/system/storage/vendor/bin/phpunit tests/phpunit/domen
```
